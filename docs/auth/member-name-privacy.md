# 이름 비공개와 프론트 연동

## 정책

- DB에는 실명(real_name)과 name_private boolean만 저장한다. 마스킹 이름을 별도로 저장하지 않는다.
- 기본값 false: 기존 회원과 신규 회원은 직접 선택하기 전까지 공개 상태를 유지한다.
- true일 때 일반 회원 응답은 김민수 → 김**, 김민 → 김*로 반환한다. 한 글자 이름은 *로 숨긴다. Unicode 코드 포인트를 중간에서 자르지 않는다.
- 본인 전용 프로필 조회/수정, 본인의 지원 페이지는 실명을 유지한다.
- 해당 프로젝트의 실제 생성자(리더)는 인증된 지원자 목록/지원 상세에서 applicantName 실명을 확인한다. 일반 팀원, 다른 프로젝트 리더는 이 API에 접근할 수 없다. 지원서 ID를 다른 프로젝트 경로에 끼워 넣어도 조회할 수 없다.
- 일반 프로필·프로젝트/팀원·Q&A·GitHub·공개 카드에서는 리더라도 마스킹을 유지한다. 리더 예외는 지원서 검토 문맥에 한정한다.
- 알림의 actorName도 마스킹한다. 수신자 본인의 receiverName은 본인에게만 전달되므로 유지한다.
- 기존 관리자 전용 운영/감사 API의 권한과 실명 조회 정책은 변경하지 않는다. 이 설정은 운영자로부터 익명성을 제공하는 기능이 아니다.
- 비공개 회원은 실명 검색 대상에서 제외한다. 직무/기술 검색에는 계속 나타날 수 있다. 프로젝트 제목 검색은 유지하고 비공개 리더 실명으로는 검색하지 않는다. 이름 정렬에서는 비공개 이름을 상수 그룹과 ID로 정렬하며 숨긴 이름 글자를 사용하지 않는다.
- 자기소개·GitHub 계정·이메일 등 사용자가 별도로 공개한 내용에서 실명을 유추하는 것까지 제거하는 기능은 아니다. 이미 조회한 데이터/스크린샷을 소급해서 지우지 않는다.

## 프론트 작업

실제 프론트 저장소에는 아직 적용하지 않았다. 앞서 전달한 학교 이름 자동 입력 패치와 함께 반영할 수 있다.

### 1. 타입과 초기 상태

`components/features/profile/profileApi.ts`의 본인 조회/수정 응답 및 수정 요청 타입에 `namePrivate`를 추가한다. 응답은 boolean, 요청은 선택적 boolean이다. 공유 타입이 있다면 함께 갱신한다.

- GET `/api/v1/members/me`: 기존 name은 본인 실명 그대로, namePrivate가 현재 설정이다.
- PUT `/api/v1/members/me`: 성공 응답에도 namePrivate가 포함된다.
- 수정 폼 초기값은 본인 GET 응답의 namePrivate에서 읽는다. 일반 사용자 상세 응답의 마스킹 이름으로 본인 폼을 만들지 않는다.
- namePrivate가 boolean으로 내려오지 않는 구버전 서버에서는 설정 지원이 확인되지 않은 것이므로 토글을 활성화하거나 비공개 저장 성공으로 표시하지 않는다. PUT 성공 응답의 namePrivate도 요청값과 일치하는지 확인한 뒤 저장 완료를 표시한다.

### 2. 토글 UI

`ProfileOverview.tsx`의 프로필 수정 폼(별도 모달 컴포넌트로 분리되어 있으면 그 컴포넌트)에 다음 항목을 추가한다.

- 라벨: 이름 비공개
- 안내: 프로젝트에 지원하면 해당 프로젝트 리더는 지원서에서 이름 전체를 확인할 수 있습니다.
- 학교 확인 이름의 읽기 전용 처리와 별개로 토글을 조작할 수 있게 한다. 이름 입력을 disabled 처리한 fieldset 안에 넣어 토글까지 비활성화하지 않는다.
- 저장 전까지 로컬 상태만 바꾸고, 저장 실패 시 성공한 것처럼 표시하지 않는다.

### 3. 수정 요청

기존 PUT의 multipart/form-data와 memberInfo JSON 파트를 그대로 사용한다. namePrivate를 독립 FormData 필드로 보내지 않는다.

```ts
const memberInfo = { ...existingProfileFields, namePrivate: isNamePrivate };
formData.set('memberInfo', new Blob([JSON.stringify(memberInfo)], {
  type: 'application/json',
}));
```

기존 필수 항목(age, gender, jobPositionIds, techStacks 등)을 포함한다. 이 PUT은 boolean 하나만 보내는 PATCH가 아니다. 학교 확인 계정은 name을 생략하거나 본인 실명 그대로 보내며 마스킹 이름을 보내지 않는다. 기존 미확인 계정의 이름 필수 정책은 유지한다.

- true: 비공개로 변경
- false: 공개로 변경
- 생략/null: 저장된 설정 유지, 과거 클라이언트가 실수로 공개 상태로 되돌리지 않음

### 4. 지원자 화면과 다른 화면

- 리더 지원자 목록: GET `/api/v1/projects/{projectId}/applications`
- 리더 지원 상세: GET `/api/v1/projects/{projectId}/applications/{applicationId}`
- 위 응답의 applicantName을 그대로 표시한다. 프론트에서 이름 비공개를 이유로 다시 마스킹하지 않는다.
- 일반 카드/프로필/Q&A/팀원/GitHub 화면도 서버가 준 name/creatorName/writerName 등을 그대로 표시한다. 브라우저의 리더 여부로 이름을 복구하거나 별도 realName을 받는 로직을 만들지 않는다.
- 응답별 이름을 memberId 하나에 전역 병합하지 않는다. 지원서에서 본 실명을 일반 공개 카드 캐시에 덮어쓰면 안 된다. 쿼리 키를 프로필/지원서/프로젝트/권한 문맥별로 나눈다.
- 저장 성공 후 본인 프로필과 공개 프로필/카드/팀원/Q&A 등 이름을 캐시한 쿼리를 invalidate/refetch한다. 로그아웃·계정 전환 시 리더 지원자 캐시를 비운다. 공유 localStorage에 지원자 실명을 저장하지 않는다.
- 일반 프로필만 조회하면 리더라도 마스킹된다. 지원자 실명이 필요하면 권한이 있는 지원서 API를 사용한다.

### 5. 프론트 검증

1. 공개 → 비공개 저장/새로고침 후 유지, 비공개 → 공개도 동작.
2. 본인은 실명과 켜진 토글을 확인, 다른 회원은 마스킹 이름 확인.
3. 실제 해당 프로젝트 리더만 지원서 실명 확인, 팀원·다른 리더는 거부.
4. 리더 지원서 캐시를 일반 프로필/공개 카드에 재사용하지 않음.
5. 학교 확인 이름은 여전히 수정 불가이고 토글은 사용 가능.
6. 기존 클라이언트가 namePrivate를 생략해도 비공개 설정이 풀리지 않음.

## DB·배포

- `V8__member_name_privacy.sql`은 name_private BIT NOT NULL DEFAULT 0 열만 추가한다. 실명과 기존 회원 데이터는 변경하지 않는다.
- 앞선 학교 프로필 변경 V7이 함께 미적용이면 이력/백업을 검토하고 V7 다음 V8 순서로 적용한다. Flyway를 임의 활성화하거나 테이블을 재생성하지 않는다.
- 백엔드와 DB를 먼저 반영한 뒤 프론트를 배포한다.
- 아직 운영 DB 적용·푸시·배포는 하지 않았다. 실제 프론트 화면 구현도 이번 작업 범위 밖이며 이 문서는 전달 계약이다.

## 검증 결과

- 격리 사본의 선별 백엔드 테스트 696개 통과(실패/오류/건너뜀 0). 이름 비공개 관련 27개가 포함된다.
- 공개 DTO의 실제 JSON 마스킹, 본인 응답, 리더 권한/다른 프로젝트 지원서 차단, 비로그인 차단, 본인 지원 폼의 인증 주체 전달, 설정 생략 시 유지, 검색/정렬 보호, 알림, V8 H2 데이터 보존을 검사했다.
- 게시된 원본 build.gradle로 Java 17 bootJar -x test 성공. 테스트 사본에만 기존 JUnit 호환 버전을 적용했다. 현재 작업 저장소의 build.gradle은 변경하지 않았다.
- 시작 시점의 변경 파일 48개 중 이번 기능이 확장하는 회원 엔티티/프로필 관련 4개 외 나머지 44개는 바이트 단위로 보존했다. 앞선 학교 인증/SSO 코드와 원래의 미완료 작업도 유지했다.
- 실제 MySQL V8 실행, 실제 서비스 API/프론트 화면, 운영 배포 검증은 하지 않았다. 기존 학교 조회 성공 기록은 별도 학교 인증 기능 검증이며 이 테스트의 실DB 검증으로 간주하지 않는다.
