# 리스크 매트릭스 기반 인수테스트 우선순위 설계

이 문서는 효율적인 ATDD(Acceptance Test-Driven Development) 수행을 위해 각 기능별 리스크를 정량적으로 평가하고, 이에 따른 테스트 우선순위를 정의한 문서입니다.

## 문서 상태

게시 GitHub `main` 커밋 `3865b451663788792d7e78c736282f8b9ff105f1` 기준의 **요구사항·테스트 우선순위 제안**입니다. 점수는 계획용 상대 평가이며 운영 장애 통계·측정된 변경 빈도·실행 커버리지에서 산출한 값이 아닙니다. 테스트 구현·통과 여부와 분리합니다. 이번 감사는 정적 검토만 수행했으며 로컬 미커밋 수정은 근거로 삼지 않았습니다.

## 1. 리스크 평가 기준 (Evaluation Criteria)

테스트 시나리오의 우선순위는 다음 4가지 지표의 합계를 통해 산출합니다. (각 항목당 1~5점 부여)

| 항목 | 설명 |
| :--- | :--- |
| **비즈니스 임팩트 (Business Impact)** | 기능 실패 시 서비스의 핵심 가치 훼손 및 보안 사고 발생 정도 |
| **코드 복잡도 (Code Complexity)** | 로직의 난이도, 의존성 결합도 및 유지보수 난이도 |
| **변경 빈도 (Change Frequency)** | 정책 변경이나 기능 고도화에 따라 코드가 수정되는 횟수 |
| **버그 가능성 (Bug Probability)** | 예외 케이스의 다양성 및 기존 구현 시 실수가 잦은 영역 |

## 3. 리스크 분석 결과 및 전략

### Priority 1: 사용자 인증 및 권한 인가
- **분석:** 서비스 전체의 관문이며, 실패 시 개인정보 노출 및 데이터 오염 등 치명적인 비즈니스 리스크를 초래합니다.
- **전략:** 가장 먼저 인수테스트를 구축하며, 정상 로그인뿐만 아니라 토큰 만료, 잘못된 토큰 접근 등 예외 케이스를 명시적으로 설계합니다. 100% 검증 또는 커버리지 달성을 주장하지 않습니다. 게시 인증 API와 레거시 인수 헬퍼의 계약 일치를 먼저 보완해야 합니다.

### Priority 3: 생성자 리더(LEADER) 권한 자동 할당
- **분석:** 프로젝트 생성 유저는 해당 팀의 관리 권한을 가져야 합니다. 이 로직이 누락될 경우 팀원이 팀을 삭제하거나 수정하는 권한 침해 문제가 발생합니다.
- **전략:** `ProjectMember` 엔티티 생성 시 `ProjectMemberRole.LEADER`가 명확히 할당되는지 DB 수준에서 검증하는 단계(Then step)를 필수적으로 포함합니다.

---

## 4. 결론
리스크 총점이 높은 **인증/인가** 및 **권한 관리**를 인수테스트의 최상위 목표로 설정함으로써, 개발 초기 단계에서 핵심 비즈니스 오류를 발견하고 서비스 신뢰성 개선을 목표로 합니다. 이는 테스트 통과·리팩토링 완료·오류 발견 실적을 의미하지 않습니다.


## 5. 게시 구현과 남은 검증

- `src/main/java/com/wardk/meeteam_backend/web/auth/controller/AuthController.java:45-85`: 실제 인증은 세종대 로그인·가입 및 쿠키 발급입니다. OAuth는 게시 인수 헬퍼에 남은 레거시 흐름이며 현재 API 계약으로 분류하지 않습니다.
- `src/main/java/com/wardk/meeteam_backend/domain/projectmember/service/ProjectMemberServiceImpl.java:33-46`: 생성자에게 `LEADER`를 저장하는 구현이 이미 있습니다.
- `src/test/java/com/wardk/meeteam_backend/acceptance/cucumber/steps/ProjectCreateSteps.java:166-179`: 리더 역할·회원 이름을 DB에서 확인하는 기존 Then이 있습니다. 이번 신규 테스트 작성이나 실행 성공의 근거가 아닙니다.
- 상세 `isLeader`, 정확한 비인증 401 응답, 생성 실패 시 롤백, 전체 feature 문장 연결 및 실행 환경 격리는 별도 검증 과제입니다. [5W1H](ACCEPTANCE_CRITERIA_5W1H.md)와 [기준 컨벤션](../../TEST_CONVENTION.md)을 함께 확인합니다.
