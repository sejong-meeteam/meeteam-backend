# 별도 관리자 계정: 기존 로그인 API 사용

## 계정 구분

- 학생: 기존 학교 인증과 일반 회원가입을 그대로 사용합니다.
- 공용 테스트 계정 `99990001`: 기존 USER 계정/비밀번호/배포 검증을 그대로 유지합니다.
- 운영 관리자: 별도의 예약 숫자 아이디와 비밀번호를 사용합니다. 개인 학번을 ADMIN으로 바꾸지 않습니다.
- 관리자 전용 로그인 API나 공개 관리자 회원가입 API는 추가하지 않습니다.

## 기존 프론트와 API 계약

기존 로그인 화면의 학번 칸에 설정한 관리자 아이디를 입력합니다. 백엔드는 기존 `POST /api/v1/auth/login/sejong`의 `studentId`, `password` 요청을 받습니다. 설정한 관리자 아이디만 학교 인증 대신 DB의 BCrypt 비밀번호를 확인합니다. 실패 시 학교 인증이나 신규 회원가입으로 우회하지 않습니다.

성공 응답과 HttpOnly Access/Refresh 쿠키는 기존 로그인과 동일합니다. `/api/v1/members/me`의 `role`은 `ADMIN`입니다. 다른 학생은 반드시 학교 인증을 거치며 일반 회원가입으로 관리자 권한이나 `local-admin` provider를 지정할 수 없습니다.

## 비공개 설정

기본값은 비활성입니다. 활성화한 배포에서만 관리자 초기화와 로그인 분기가 생성됩니다. 실제 설정/계정 생성은 별도 승인과 적용이 필요하며, 이 문서 자체가 서버 반영 완료를 뜻하지 않습니다.

### 본인이 비밀번호를 직접 설정하는 권장 방법

새 코드가 배포된 뒤 **EC2 서버의 일반 터미널**에서 실행합니다. Mac 로컬 프로젝트에서 실행하는 명령이 아닙니다.

```bash
bash /home/ubuntu/meeteam/tools/setup-admin-account.sh
```

도구가 요청하면 새 비밀번호를 두 번 입력하고 각각 Enter를 누릅니다. **입력 중 글자나 별표가 보이지 않는 것이 정상**입니다. 비밀번호를 채팅, 명령 인수, Git 또는 문서에 적지 않습니다. 이 서버 도구는 승인된 관리자 아이디 `99990002`를 사용합니다.

비밀번호 입력은 실행 중인 앱이 아니라 네트워크가 차단된 일회성 컨테이너에서 처리합니다. 평문은 파일이나 서버 환경변수에 저장하지 않고 BCrypt cost 12 해시만 0600 권한의 비공개 `.env.admin-account`와 DB에 저장합니다. 설정 후 앱만 재기동하고 정상 상태와 동일한 저장 해시를 검사합니다. 기존 DB/Redis 컨테이너나 학생/테스트 계정은 변경하지 않습니다.

실패 시 기존 앱 구성을 복구하고 `.env.admin-account.pending`에 같은 해시를 보관합니다. 초기화 중 관리자 행이 이미 생겼을 수 있으므로 DB 행을 지우거나 다른 비밀번호로 덮어쓰지 않습니다. 복구 상태를 검토한 뒤 아래 명령으로 같은 설정을 재시도합니다.

```bash
bash /home/ubuntu/meeteam/tools/setup-admin-account.sh --resume
```

이미 활성화된 계정의 비밀번호 교체 도구는 아닙니다. 재설정/권한 버전 갱신은 별도 승인된 운영 절차가 필요합니다. 설정 전에는 관리자 기능이 기본 비활성이고, 배포 자체가 관리자 비밀번호를 정하거나 계정을 생성하지 않습니다.

- 아이디: 99로 시작하는 8자리 숫자. `99990001`은 사용할 수 없습니다. 해당 아이디를 사용한 기존 학생 행이 있으면 탈퇴 여부와 무관하게 초기화를 거부합니다.
- 비밀번호: 공백만 있는 값은 거부하며 20자 이상, UTF-8 기준 최대 72바이트입니다. 추측 가능한 문자열 대신 비밀번호 관리자로 만든 랜덤 값을 사용합니다.
- Mac 로컬 테스트와 EC2 배포 설정은 별개입니다. 실제 계정은 대상 서버의 비공개 런타임 설정에 값을 넣고 앱을 재시작해야 생성됩니다.
- 새 배포 스크립트는 비공개 `.env.admin-account`가 있을 때만 기존 앱의 env_file에 추가하여 이후 배포에도 보존합니다. 이 파일은 설정 도구가 생성합니다. BCrypt의 `$`가 Compose에서 변형되지 않도록 해시는 반드시 단일 따옴표로 감쌉니다. 기존 `.env`와 `.env.test-account`는 그대로 유지합니다.
- 비공개 파일 접근은 운영자로 제한하고 0600 권한을 사용합니다. 비밀번호를 공유하지 않습니다.

## 초기화와 충돌 방어

애플리케이션 설정은 `admin-account.enabled`, `username`, `password-hash`를 사용합니다. 기존 비공개 평문 `password` 설정 방식은 호환 목적으로 지원하지만, 두 자격 증명 소스를 동시에 지정하면 거부합니다. 권장 서버 설정 도구는 해시 방식만 사용합니다.

명시적으로 활성화하면 앱 시작 시 내부 이메일 `meeteam-admin@example.invalid`, provider `local-admin`, 학번 null, 역할 ADMIN인 회원을 한 번 생성합니다. DB에는 평문 비밀번호 대신 BCrypt 해시를 저장합니다. 내부 이메일은 로그인 아이디가 아니며 실제 메일을 수신하지 않습니다.

다시 시작할 때 기존 계정의 비밀번호·역할·식별자를 검증하고 그대로 유지합니다. 기존 일반 회원을 승격하거나, 탈퇴한 관리자를 되살리거나, 다른 비밀번호로 덮어쓰지 않습니다. 충돌하면 시작을 실패시킵니다. 환경변수의 비밀번호만 바꾸는 것은 비밀번호 변경 절차가 아닙니다.

초기화는 SERIALIZABLE 트랜잭션을 사용합니다. 복수 인스턴스의 초기화 충돌은 덮어쓰기 재시도 대신 실패할 수 있습니다. 실제 MySQL의 동시 초기화/교착 동작은 별도 검증 대상이며 H2 결과만으로 보장하지 않습니다. 기존 스키마의 `member` 필드를 사용하므로 새 테이블/컬럼 마이그레이션은 추가하지 않습니다.

## 접근과 계정 보호

- 비밀번호가 일치해도 정지/탈퇴/역할/식별자 상태가 잘못되면 로그인하지 못합니다. 기존 JWT의 회원 ID·권한 버전·역할 검증을 그대로 사용합니다.
- 인스턴스당 1분에 최대 5회 로그인 시도를 허용하며 성공도 포함합니다. 재시작/다중 인스턴스에 걸친 분산 제한이나 MFA를 구현한 것은 아닙니다. 운영 적용 시 외부 속도 제한과 MFA 검토가 필요합니다.
- `ADMIN_ACCOUNT_ENABLED=false`를 반영해 재시작하면 전용 관리자 로그인뿐 아니라 기존 관리자 Access Token 사용 및 Refresh Token 재발급도 차단됩니다. DB 회원을 삭제하거나 다른 계정을 변경하지 않습니다.
- 다시 활성화하면 아직 유효한 옛 토큰이 허용될 수 있습니다. 영구적인 세션 폐기/비밀번호 교체에는 별도 권한 버전 갱신과 승인된 운영 절차가 필요합니다.
- 전용 관리자는 공개 회원 목록/검색/상세에 노출하지 않습니다. 본인의 `/members/me`는 조회할 수 있습니다.
- 학생용 자기소개 등록·탈퇴/하드 삭제 경로로 전용 관리자 계정을 수정하거나 지울 수 없습니다. 관리자 화면에서도 예약 전용 계정을 임의 강등/강제 탈퇴시키지 않습니다. 계정 폐기는 별도 운영 절차로 수행합니다.
- 일반 메서드 로깅 Aspect에서 인증 컨트롤러/서비스의 인수·결과·예외 내용을 로깅하지 않고, 로그인 요청 로그에 아이디를 기록하지 않습니다. 기존 기록을 삭제하거나 기존 비밀번호를 자동 변경한 것은 아닙니다.

## 비밀번호 직접 설정 추가 검증

- 해시 전용 설정, 재초기화 일치 검사, 평문/해시 충돌 거부, 파일 덮어쓰기·심볼릭 링크 거부, 0600 권한, 터미널 없는 실행 거부 테스트를 추가했습니다. 관리자 로그인 57개 + 기존 회귀 502개, **Java 559개 통과**, 실패/오류/건너뜀 0입니다.
- 실제 배포 JAR의 `PropertiesLauncher`로 합성값을 두 번 숨김 입력했고 해시 파일 형식/0600 권한을 확인한 뒤 임시 파일을 삭제했습니다. 실제 관리자 비밀번호나 계정은 설정하지 않았습니다. 원본 빌드 설정의 Java 17 bootJar도 성공했습니다.
- 배포 오프라인 검사 14개와 초기 설정/복구 오프라인 검사 27개가 통과했습니다. 원격 Docker/EC2 앱 재기동은 이 오프라인 결과만으로 검증되었다고 주장하지 않습니다.
- 확인 시점의 프론트 main `components/features/auth/schema.ts`는 로그인 비밀번호가 비어 있지만 않으면 허용하며 숫자 아이디를 받습니다. `LoginForm.tsx`/`BaseInput.tsx`에도 별도 최대 길이가 없어 `99990002`와 20자 이상 비밀번호가 새 API 없이 기존 요청 형식과 호환됩니다. 실제 사용자의 비밀번호 입력/로그인 검증과는 별개입니다.
- EC2 명령은 배포 디렉터리 소유자 `ubuntu`로 직접 실행합니다. `sudo`/root 실행은 이후 배포에서 비공개 설정을 못 읽는 문제를 막기 위해 거부합니다.
