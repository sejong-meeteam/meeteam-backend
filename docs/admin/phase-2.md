# 관리자 기능 2단계: 회원 정지, 노출 관리, 감사 로그

> 이후 권한 변경과 강제 조치 구현은 [3단계](phase-3.md)를 참고하세요. 아래 남은 작업 목록은 2단계 당시 기준입니다.

## 로컬 구현 범위

| API | 기능 |
|---|---|
| POST /api/v1/admin/members/{id}/suspend | 1~365일 또는 영구 정지 |
| POST /api/v1/admin/members/{id}/unsuspend | 정지 해제 |
| PATCH /api/v1/admin/projects/{id}/visibility | VISIBLE/HIDDEN/DELETED 변경 및 복구 |
| GET /api/v1/admin/audit-logs | 조치·대상 유형·대상 ID 필터와 페이지 조회 |

- 사유는 공백 제거 후 5~200자입니다. 문자열 숫자나 소수 기간을 정수로 바꾸지 않습니다.
- 변경 응답은 프론트 타입에 맞춘 갱신 요약입니다. 목록 응답에는 전체 학번을 노출하지 않습니다.
- 상태 변경과 감사 로그는 같은 트랜잭션입니다. 로그 저장에 실패하면 상태 변경도 롤백합니다.
- 감사 로그에는 당시 관리자/대상의 ID와 이름, 조치, 사유, 부가 정보, 시각을 저장합니다.
- 자기 정지, 중복 조치, 잘못된 대상·상태를 거절합니다. 관리자 조치는 일정한 순서로 잠그고 다시 조회하여 동시 상호 정지를 방지합니다.

## 기존 기능에 적용한 정책

- 정지 회원은 올바른 인증 이후에도 로그인 403 MEMBER_SUSPENDED(기간과 사유 포함), 인증 요청 401입니다.
- 정지 만료 시 effective ACTIVE로 처리합니다. 오래된 정지 기록을 읽는 과정에서 DB를 변경하지 않습니다.
- 정지/해제 시 authVersion을 바꾸며 access/refresh 토큰 모두 버전과 회원 ID를 확인합니다. 정지 해제 후에도 옛 토큰은 살아나지 않습니다.
- 성공한 로그인에만 lastLoginAt을 기록합니다. 과거 로그인 시각은 만들지 않습니다.
- 공개 회원 검색/메인 목록에서 정지·탈퇴 회원과 ADMIN을 제외합니다.
- 숨김·삭제 프로젝트는 검색/메인/상세/좋아요/프로필 카드에서 제외합니다. 지원·팀 관리·Q&A의 우회 접근도 차단합니다.
- 관리자 조회는 숨김·삭제 자료도 확인할 수 있습니다. 정지 상태와 로그인 시각 정렬은 실제 필드를 사용합니다.
- 모집 상태와 관리자 노출 상태는 별개입니다. 숨김·삭제·복구로 모집 상태를 덮어쓰지 않습니다.
- 기존 isDeleted는 visibility와 함께 갱신합니다. Project 버전 필드로 오래된 일반 수정이 관리자 조치를 덮어쓰지 않도록 합니다.
- GitHub 관련 데이터나 권한은 이번 단계에서 호출·변경하지 않습니다.

## DB 변경 SQL: 아직 서버에 적용하지 않음

파일: `src/main/resources/db/migration/V3__admin_moderation_and_audit.sql`

- member: suspended, suspended_until, suspend_reason, last_login_at, auth_version 추가.
- project: visibility, version 추가. 기존 is_deleted를 바탕으로 VISIBLE/DELETED를 채웁니다.
- admin_audit_log 테이블과 조회 인덱스 추가.
- 기존 테이블/컬럼 삭제나 회원·프로젝트 내용 삭제는 하지 않습니다.

**이 코드는 DB 변경 없이 기존 서버에 바로 배포하면 안 됩니다.**

적용 전 단계:
1. 실제 대상 DB와 백업·복구 가능 여부 확인.
2. 현재 컬럼과 Flyway 이력 확인. V1/V2에는 정리·삭제 SQL이 있어, 빈 이력에 Flyway를 무작정 활성화하지 않습니다.
3. 격리한 MySQL 8 환경에서 기존 스키마에 V3를 적용해 데이터와 Hibernate validate 검증.
4. 적용 승인 후 백업을 남기고 DB 변경 및 앱 배포. MySQL DDL은 트랜잭션 롤백을 보장하지 않으므로 실패 시 자동 재실행하지 않습니다.

이번 검증은 H2 임시 DB와 가짜 외부 의존성을 사용합니다. 실제 MySQL 마이그레이션, 실제 프론트/API 연결, 서버 배포 성공을 뜻하지 않습니다.
