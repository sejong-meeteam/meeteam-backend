# 관리자 기능 1단계: 권한과 기본 조회

> 아래 한계는 1단계 당시 기준입니다. 정지·노출 상태와 감사 로그의 후속 구현은 [2단계](phase-2.md)를 참고하세요.

## 기준과 범위

- 백엔드 기준: `ffa7a98`, 프론트 계약 기준: `c5c0e4b`의 `types/admin.ts`.
- 첨부 `backend-handoff.md`와 프론트 요청 검증 규칙을 참고했습니다.
- 로컬 코드만 변경합니다. 실서버 DB 변경, 관리자 계정 생성, 커밋·푸시·배포는 포함하지 않습니다.
- 관리자 화면 전체가 완성된 것은 아닙니다. 대시보드와 변경 API 등 미구현 화면은 아직 실제 API로 전환하면 안 됩니다.

## 구현

- `/api/v1/admin` 및 하위 경로는 현재 DB 권한이 `ADMIN`인 사용자만 접근할 수 있습니다.
- 비로그인 401, 일반 회원 403 `ADMIN403`. CORS 사전 요청은 인증을 요구하지 않습니다.
- `/api/v1/members/me` 응답에 기존 역할 `USER` 또는 `ADMIN`을 추가합니다.
- 실패 응답에는 명시적인 `result: null`을 추가합니다. 기존 `code`, `message`는 유지됩니다.

| 조회 API | 기능 |
|---|---|
| GET /api/v1/admin/members | 검색, 상태·역할·대표 직군 필터, 정렬, 페이지 조회 |
| GET /api/v1/admin/members/{memberId} | 회원 상세, 참여 프로젝트, 지원 내역 |
| GET /api/v1/admin/projects | 검색, 카테고리·모집·노출 상태 필터, 정렬, 페이지 조회 |
| GET /api/v1/admin/projects/{projectId} | 프로젝트 상세, 팀원, 모집 현황, 지원 상태별 수 |

- 목록에서는 학번 앞 4자리만 노출하고 나머지는 `*`로 가립니다. 상세에서는 전체 학번을 반환합니다.
- 실제 DB에서 필터·정렬·페이지 처리를 합니다. 사용자가 입력한 값은 쿼리 파라미터로 바인딩합니다.
- `%`, `_`, `!` 검색은 와일드카드가 아니라 입력한 문자 그대로 처리합니다.
- page 기본 0. 음수·잘못된 page와 50자를 넘는 검색어는 400 `ADMIN_INVALID_REQUEST`입니다.
- size 기본 10, 최대 50입니다. 0·숫자 아닌 값은 기본값, 음수는 1로 정규화합니다.
- 잘못된 필터·정렬은 전달 문서에 따라 무시하고 기본 조건으로 처리합니다.
- 없는 대상은 404 `ADMIN_TARGET_NOT_FOUND`입니다.
- 리더 정보가 없는 비정상 프로젝트는 가짜 ID나 계약에 없는 null을 반환하지 않고 409 `ADMIN_INVALID_STATE`로 처리합니다.

## 현재 데이터 모델의 한계

이번 단계는 DB 구조를 바꾸지 않습니다.

- 회원은 `deletedAt`으로 ACTIVE/WITHDRAWN만 구분합니다. 정지 상태·사유·기간은 다음 단계입니다.
- 프로젝트는 `isDeleted`로 VISIBLE/DELETED만 구분합니다. HIDDEN과 복구는 다음 단계입니다.
- SUSPENDED 회원과 HIDDEN 프로젝트 필터는 현재 저장 가능한 대상이 없어 빈 목록을 반환합니다.
- `suspendedUntil`, `suspendReason`, `lastLoginAt`은 null입니다. 과거 로그인 시각을 임의로 만들지 않습니다.
- `lastLoginAt,desc`는 모두 null인 상태이므로 생성 시각 내림차순과 ID 내림차순으로 정렬합니다.
- 대표 직무 순서 필드가 없어 직무 연결 ID가 가장 작은 항목을 대표로 사용합니다.
- 회원의 프로젝트 수는 삭제되지 않은 프로젝트의 생성자 또는 참여자인 경우를 중복 없이 셉니다.

## 검증

- `adminsecurityunit`: 실제 SecurityFilterChain과 JWT 필터를 통과하는 MockMvc 권한·응답 검사.
- `adminqueryunit`: 요청 정규화, 학번 마스킹, JSON 형식, 임시 H2 DB 조회 검사.
- DB 테스트는 H2만 사용하며 실제 MySQL·Redis·S3는 호출하지 않습니다.
- 기존 미완료 테스트와 분리한 임시 빌드에서 관리자 테스트와 기존 인증·이미지 테스트를 함께 실행합니다.
- 전체 기존 인수·통합 테스트와 실제 프론트 연결은 별도 검증 항목입니다.
