# 관리자 기능 5단계 검증 결과

## 범위

- 실제 MySQL 8.0.46과 Redis 7을 작업 전용 Docker 컨테이너로 생성했습니다.
- 기존 사용자 컨테이너, 실서버 DB/Redis, AWS 자원, 배포 설정은 변경하지 않았습니다.
- 모든 DB 자료는 검증용 가상 데이터입니다. 운영 데이터를 복사하지 않았습니다.
- 검증 뒤 전용 서버와 컨테이너를 정리합니다.

## 실제 MySQL 마이그레이션

1. 게시된 백엔드 ffa7a98의 엔티티로 빈 검증 DB에 기존 스키마를 생성했습니다.
2. 가상 회원 3명과 프로젝트 2개를 넣고, 기존 20개 테이블의 행과 모든 원래 컬럼 값을 저장했습니다.
3. 현재 V3와 V4 SQL을 적용했습니다.
4. 기존 5개 행의 원래 컬럼 값 91개가 그대로 유지됐음을 대조했습니다.
5. 기존 soft-delete 값에 따른 프로젝트 노출 상태, 새 컬럼의 기본값과 빈 감사 로그를 확인했습니다.
6. 현재 엔티티 전체에 대해 Hibernate 6.6.13.Final의 hbm2ddl=validate가 통과했습니다.

실행된 마이그레이션 문장은 V3 4개, V4 1개입니다. MySQL 실제 타입 검증도 통과했으며, 이번 확인으로 V3/V4 원본을 수정하지는 않았습니다.

이것은 **코드에서 생성한 기존 스키마**에 대한 검증입니다. 실서버의 실제 스키마, Flyway 이력, 추가 제약조건과의 일치를 검증했다는 뜻은 아닙니다.

## 실제 HTTP와 프론트

- 임시 백엔드는 새 MySQL/Redis에 연결하고 ddl-auto=validate, SQL 초기화 비활성으로 실행했습니다.
- 세종 포털과 S3 클라이언트만 검증용 대체 객체를 사용했습니다. 실제 포털이나 AWS로 요청하지 않았습니다.
- 가상 계정으로 실제 로그인 컨트롤러, JWT, HttpOnly 쿠키, 프록시, 관리자 화면을 연결했습니다.
- 프론트 c5c0e4b는 MSW를 끄고 실제 백엔드 API를 호출했습니다.
- 로컬 주소는 localhost:13005, 백엔드는 127.0.0.1:18888이었습니다. 프록시 Origin 검사 때문에 브라우저 호스트를 localhost로 통일했습니다.
- macOS 네이티브 모듈 로딩 제한으로 임시 node_modules의 SWC/CSS 모듈에 WASM 대체를 사용했습니다. 프론트 소스, manifest/lockfile, 배포 설정은 변경하지 않았습니다.

| 항목 | 결과 |

| 비로그인 관리자 대시보드 | 401 |

## 아직 남은 검증

- 실제 MySQL/프론트에서 권한 변경·강제 탈퇴·강제 마감·팀원 제외의 전체 조합. 해당 기능은 기존 선별 단위/H2 테스트와 구분합니다.
- 실제 세종 포털 및 S3 이미지 처리.
- 실서버 스키마·시간대·Flyway 이력, 백업/복구 확인과 첫 관리자 계정 준비.
- 실제 배포 환경의 Node 24/네이티브 프론트 빌드 및 쿠키·Origin 설정.
- 전체 인수·통합 테스트와 GitHub 연동.

커밋·푸시·실서버 DB 적용·배포는 하지 않았습니다. 기존 미완료 작업은 보존했습니다.
